Issue [#10](https://github.com/GroovierHen/kept/issues/10) ("Sign-up saves the time zone and records the first Event") is committed as `86bdd23` on a new branch, `feat/signup-time-zone-event`, but one criterion is still open: RLS on the `events` table. I branched rather than committing to `main` because the migrations job runs on PRs. Nothing is pushed.

**What now works**
- **Time zone:** the sign-up and sign-in forms send the browser's time zone. It's validated with `resolveTimeZone`, falls back to Europe/London if invalid or missing, and is only written when the user row is created.
- **Signed up Event:** the user row and its Event are saved in one transaction, and only once.
- **Event list:** [kept-events.ts](src/server/events/kept-events.ts) holds the nine Event names with a strict contract for each. `recordEvent` is in [record-event.ts](src/server/events/record-event.ts) and takes the transaction as an argument.
- **Schema:** `User` moved to [act.prisma](prisma/schema/act.prisma) with the spec's fields, and `example.prisma` is gone.

**How it was tested**
- **Local checks:** lint, typecheck, formatting, standards and build all pass, and so do all 224 unit tests.
- **Real database:** I ran `provisionUser` against a throwaway Postgres. These all behaved correctly:
    - a new user's time zone is stored
    - a later sign-in leaves it unchanged
    - invalid or missing zones fall back
    - a failed Event rolls the user back
    - concurrent first sign-ins record one Event
- **Browser:** the sign-up page's hidden field held `Asia/Karachi` with no console errors.
- **Not tested:** a full sign-up through Supabase, because `.env.local` points at the real project. That is the job of the #15 browser test. The database checks were a scratch script and aren't committed, as the spec adds no database test layer this week.

**What's still open**
- **RLS on `events`:** CI writes the create migration on push, and the RLS migration has to come after it. `check:rls` passed locally only because I enabled RLS by hand on the throwaway database. It will be red in CI until that migration lands.
- **Deploy order:** sign-up and sign-in will fail if the app deploys before the migration runs. The PR needs to say so.
