**Temperature is a setting that controls how much randomness an AI model uses when it writes.** A low value makes it stick to its most likely wording, and a high value lets it make less obvious choices.

A model writes one small piece of text at a time, and at each step it has several possible next words, each with a likelihood. For example, after "Run slowly to...":

- **Low temperature:** it almost always picks the most likely word, like "build". The same request gives very similar answers each time.
- **High temperature:** it picks less likely words more often, like "protect" or "enjoy". Answers vary more and are less predictable.

## How Kept uses it
[generate-plan.ts](src/server/learn/generate-plan.ts:14) sets two values:

| When | Temperature | Why |
|---|---|---|
| First plan | 0.4 | Two people with the same goal get similar plans, but the wording doesn't sound robotic |
| Try again | 0.9 | Someone asking for a new plan wants a noticeably different one |

So in Kept, temperature is the setting that makes a Try again plan differ from the first one.

## What changes with Luna
Luna's OpenRouter listing doesn't include `temperature` as a supported setting, so Kept couldn't ask for 0.4 or 0.9. In my benchmark I left it out for Luna, and it still passed every test.

The effect on Try again is what I haven't tested. Luna's plans for the same goal did differ between benchmark runs, with about 40% of the words in their medium-sized actions overlapping on average. But those were repeat runs, and a real Try again might still come out too close to the first plan.

If it does, the simple fix is to change the Try again prompt to say something like "write a different plan from this one", and include the first plan. That should push it to differ more directly than temperature does, but it would need testing too.
