## The two fixes (branch `fix/auth-failure-modes`, 2 commits)

**1. A slow phone saves the wrong time zone, for good.**
* **What happens:** the sign-up form shows before its JavaScript loads. If someone submits in that gap, no time zone is sent, and London is stored permanently.
* **Before:** a browser set to Karachi with JavaScript off was stored as `Europe/London`. Its Kept day would roll over at 9am Karachi time instead of 4am.
* **Fix:** when the browser sends nothing, use the zone Vercel works out from the visitor's IP (the `x-vercel-ip-timezone` header). London is now the last resort.
* **Test:** `resolveTimeZone('', 'Asia/Karachi')` failed on the old code (it returned `Europe/London`) and passes now.
* **After:** the same browser run stored `Asia/Karachi`.

**2. Sign-up half-succeeds and the person is stuck forever.**
* **What happens:** Supabase creates the account and opens the session, then saving our `users` row fails.
* **Before:** I made the `users` insert fail for one email. That person was signed in, saw no error, walked setup to the reminder step, and was stuck there. There was no `users` row and no `signed_up` event, so they would never show on the results page.
* **Fix:** if the save fails, sign them out again, so they see "Something went wrong" and can retry. This applies to sign-up and sign-in.
* **Tests:** three, covering a failed save, a successful save, and the sign-out itself failing. These are unit tests on the new function. The repo has no way to test server actions against a real database, so the reproduction for this one is the browser run.
* **After:** an error was shown and the person stayed signed out. Once the database was healthy again, one sign-in saved the row and the event, and setup finished on Today.

All 235 tests, typecheck and lint pass.
